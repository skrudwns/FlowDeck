# ADR-0003: 실데이터 수집기 실행 위치

- 날짜: 2026-10-23
- 상태: 채택
- 관련: #2, ADR-0002

## 상황

- 분석에 쓸 가격 데이터를 몇 주 동안 끊김 없이 쌓아야 한다 (#2).
- 노트북이 꺼져 있어도 주기적으로 수집 코드를 실행해 줄 곳이 필요하다.
- 이 단계에서 비용을 들일 계획은 없다.
- 수집 주기는 1시간에 한 번이면 충분하다고 봤다.

## 선택지

### A. 노트북에서 cron으로 실행

- 좋은 점: 비용이 없고 바로 할 수 있다.
- 걸리는 점: 노트북이 잠자기 상태이거나 꺼져 있으면 수집이 빈다. 연속 데이터가 필요한 목적에 맞지 않는다.

### B. 클라우드 서버를 빌려 수집기와 DB를 상시 실행

- 좋은 점: 거의 끊기지 않는다. 나중에 포털(API, 웹)도 같은 서버에 올릴 수 있다.
- 걸리는 점: 월 5달러 안팎의 비용이 든다. 무료 등급(Oracle 등)은 가입 때 카드 등록이 필요하다. 서버 생성, Docker 설치, 보안 설정을 직접 해야 한다.

### C. GitHub Actions 예약 실행 + 관리형 Postgres(Neon)

- 좋은 점: 무료 범위 안에서 된다. 관리할 서버가 없다. 수집 데이터는 Neon DB에 쌓이므로 나중에 포털도 같은 DB에 연결하면 된다.
- 걸리는 점: GitHub 부하가 높을 때 예약 실행이 늦어질 수 있다. 포털을 만들 때 수집 실행 위치를 한 번 옮기게 될 가능성이 크다.

## 결정

C. 비용을 들이지 않는다는 조건에서 끊김이 가장 적은 방법이다.

포털이 생기기 전까지 데이터를 쌓아 두는 임시 방식으로 본다. 포털에 수동 실행, 주기 변경 기능이 들어가면 작업 스케줄러가 생기는데, 그때 수집도 그쪽으로 옮길지 다시 정한다.

## 무료 한도 (2026-10-23 확인)

GitHub Actions ([문서](https://docs.github.com/en/actions/writing-workflows/choosing-when-your-workflow-runs/events-that-trigger-workflows), [요금](https://docs.github.com/en/billing/concepts/product-billing/github-actions)):

- 비공개 저장소는 GitHub Free 기준 월 2,000분 포함. 공개 저장소는 무료.
- 예약 실행 최소 간격은 5분.
- "The `schedule` event can be delayed during periods of high loads"
- "High load times include the start of every hour. If the load is sufficiently high enough, some queued jobs may be dropped." (2026-10-24 추가. 그래서 워크플로는 매시 17분에 돌린다)
- 예약 워크플로는 기본 브랜치(main)에서만 실행된다.
- 공개 저장소는 60일 동안 활동이 없으면 예약 워크플로가 자동으로 꺼진다.

Neon Free ([FAQ](https://neon.com/faqs/free-plan-limits-and-quotas)):

- 프로젝트당 저장 공간 0.5GB, 컴퓨트 월 100 CU-hours.
- 5분 동안 요청이 없으면 컴퓨트가 멈추고, 멈춘 동안은 컴퓨트 사용량이 쌓이지 않는다.

## 감수하는 것

- 실행 시간: 1시간마다 실행하면 월 720회다. 한 번에 1분 정도 걸린다고 보면 월 720분 정도로 2,000분 안에 들어간다. 실제 실행 시간은 첫 실행 후 측정해서 여기에 적는다.
- 저장 공간: 0.5GB가 가장 먼저 부딪힐 한도다. 수집 대상 수와 저장 방식(가격이 바뀌지 않아도 매번 저장할지)을 정할 때 이 한도를 기준으로 계산한다.
- 예약 실행이 늦어지거나 빠지는 시간대가 생길 수 있다. 분석할 때 수집 시각 간격이 고르지 않다는 걸 전제로 해야 한다. 실행 기록을 남겨 얼마나 빠졌는지 나중에 확인한다.
- 예약 실행은 main에서만 돌기 때문에, 이 브랜치의 수집기가 main에 합쳐진 뒤부터 수집이 시작된다.
- 네이버 API 키와 DB 접속 정보는 GitHub 저장소의 Secrets에 넣어야 한다. 이 값은 저장소 주인이 직접 넣는다.
