# ADR-0004: 실데이터 소스 다시 정하기

- 날짜: 2026-10-24
- 상태: 채택
- 관련: #2, ADR-0002(폐기)

## 상황

- ADR-0002에서 고른 네이버 쇼핑 검색 API가 2026-07-31에 종료돼 있었다.
- 같은 실수를 하지 않으려고, 이번에는 후보마다 공식 페이지와 실제 접근 결과를 먼저 확인했다.
- 조건은 그대로다. 몇 주 동안 끊김 없이 쌓을 것, 비용 없이 GitHub Actions에서 돌릴 것 (ADR-0003).

## 조사 결과

### 공식 API

11번가 OpenAPI

- 개발자 센터(openapi.11st.co.kr) 가이드에 "상품검색" API가 공개돼 있다. 키워드로 검색하고, 한 번에 최대 200개, 낮은가격순 정렬도 있다. 응답 예시에 가격과 상품 번호(`prdNo`)가 들어 있다.
- 오류 코드에 `004 overedTraffic` "하루 호출 가능 회수를 초과했습니다"가 있어서 일일 한도가 있다. 숫자는 확인하지 못했다.
- 2026-06-24 공지 "[중요] 11번가 OpenAPI 인증키 유효기간(180일) 정책 적용 안내 (6/30 시행)"가 있다. 키를 180일마다 갱신해야 하는 것으로 보이지만, 공지 본문은 읽지 못했다.
- 키 발급은 11번가 로그인 후 서비스 등록 화면에서 한다. 일반 회원도 받을 수 있는지, 판매자만 되는지는 확인하지 못했다.
- 2026-10-24 서비스 등록을 직접 시도했다.
  - 등록 화면에 "접속권한" 항목이 필수다. "셀링툴 업체 선택" 또는 "IP 직접 입력" 중 하나를 고르고, IP 직접 입력은 개발서버 IP, 개발자 PC, 상용서버 IP를 적는다. 등록한 IP에서만 호출되는 구조로 보인다.
  - 이 Mac의 공인 IP를 넣고 등록했지만 "시스템 오류"로 등록되지 않았다. 원인은 모른다.
  - IP를 등록해야 한다면 실행할 때마다 IP가 바뀌는 GitHub Actions(ADR-0003)에서는 호출할 수 없다. 고정 IP 실행 환경은 유료다.

쿠팡 파트너스 API

- 쿠팡 공식 가이드를 인용한 글(2026-09 확인)에 따르면 "최종 승인이 완료되어야 … 파트너스 API 이용이 가능"하다. 최종 승인 심사는 누적 판매 15만 원이 되면 시작된다.
- 이 프로젝트에서 판매 실적을 만들 방법이 없으므로 사실상 쓸 수 없다.
- 출처: https://uup.kr/blog/coupang-partners-api-key (쿠팡 가이드 원문은 직접 보지 못함)

### 직접 수집

robots.txt는 2026-10-24에 이 Mac에서 curl로 받았다. 우리 수집기는 별도 봇 이름이 없으므로 `User-agent: *` 규칙을 기준으로 봤다.

| 사이트 | robots.txt (`*` 기준) | 접근 결과 | 비고 |
|---|---|---|---|
| 쿠팡 | 확인 불가 | robots.txt 요청부터 403 Access Denied | |
| 11번가 | `Disallow: /` | 200 | 검색엔진 봇만 허용 |
| SSG | `Disallow: /` | 200 | |
| 롯데온 | `Disallow: /` | 200 | |
| 무신사 | `Disallow: /` | 200 | |
| 스마트스토어 | `Disallow: /` | 200 | |
| 네이버 쇼핑 검색 | 확인 불가 | 418 | |
| 올리브영 | 확인 불가 | 403, "잠시만 기다려 주세요" 대기 화면 | |
| G마켓, 옥션 | `Allow: /` | robots.txt는 200, 메인 페이지는 403 | Cloudflare 관리 규칙. `Content-Signal: search=yes,ai-train=no,use=reference` |
| 다나와 | 대부분 허용. `/api/`, `/list/ajax/`, `/info/ajax/` 등만 금지 | 200 | 가격비교 사이트 |
| 에누리 | `Allow: /` | 200 | 가격비교 사이트 |
| 컬리 | `Allow: /` (마이페이지, 주문 등 제외) | 200 | |

이용약관:

- 다나와(https://www.danawa.com/info/provision.html): "자동", "크롤", "로봇", "수집" 같은 단어로 찾아봤을 때 자동 수집을 직접 금지하는 조항은 없었다. 대신 "이용자는 '회사'를 이용함으로써 얻은 정보 중 '회사'에게 지적재산권이 귀속된 정보를 '회사'의 사전 승낙 없이 복제, 송신, 출판, 배포, 방송 기타 방법에 의하여 영리목적으로 이용하거나 제3자에게 이용하게 하여서는 안됩니다."라는 조항이 있다.
- 에누리, 컬리: 약관 페이지가 스크립트로 그려져서 이번에 원문을 읽지 못했다.
- 법적 판단은 하지 않았다. 참고한 일반론: 약관도 계약처럼 효력이 인정될 수 있고, 차단 조치를 우회해 수집하면 부정경쟁방지법 문제가 될 수 있다 (https://www.innoforest.co.kr/report/NS00000366/).

## 선택지

### A. 11번가 상품검색 API

- 좋은 점: 공식 API. 가격과 상품 번호가 있어 같은 상품을 시점별로 추적할 수 있다. 온라인 셀러 시나리오와 맞는다.
- 걸리는 점: 일반 회원이 키를 받을 수 있는지 모른다. 일일 한도 숫자를 모른다. 키를 180일마다 갱신해야 할 수 있다. 호출할 IP를 미리 등록해야 해서 GitHub Actions에서 돌릴 수 없다. 등록 시도는 "시스템 오류"로 실패했다.

### B. 다나와 직접 수집

- 좋은 점: robots.txt가 상품 페이지 수집을 막지 않는다. 가격비교 사이트라 상품 하나에 여러 판매처 가격이 같이 있어서 경쟁사 가격 모니터링과 잘 맞는다. 외주에서 많이 요구하는 직접 수집을 보여줄 수 있다.
- 걸리는 점: 화면 구조가 바뀌면 수집이 깨진다. 약관의 영리 목적 복제 금지 조항이 있다. 이 프로젝트는 영리 서비스가 아니지만, 수집 데이터를 외부에 다시 배포하지 않는 쪽으로 범위를 잡아야 한다. GitHub Actions 서버에서 접근했을 때 막히는지는 아직 모른다.

### C. 쿠팡 파트너스 API

- 판매 실적 조건 때문에 제외.

### D. robots.txt가 막거나 접근이 막힌 쇼핑몰 직접 수집

- 쿠팡, 11번가 화면, SSG, 롯데온, 무신사, 스마트스토어, 올리브영, G마켓·옥션 메인. 제외.

## 결정

B. 다나와 직접 수집.

- A(11번가)는 등록 시도가 "시스템 오류"로 실패했고, IP 등록이 필요해서 GitHub Actions에서 돌릴 수 없다.
- 다나와는 robots.txt가 상품 페이지 수집을 막지 않고, IP 제한이 없어서 ADR-0003 계획을 그대로 쓸 수 있다.

## 법적 위험과 수집 원칙

법률 검토를 받은 건 아니다. 아래는 찾아본 판례와 일반론을 바탕으로 한 판단이다.

참고한 판례: 야놀자-여기어때 사건 (대법원 2022. 5. 12. 선고 2021도1533)

- 경쟁사인 여기어때가 야놀자 숙박업소 정보를 크롤링으로 246회 복제한 사건.
- 형사(정보통신망법, 저작권법 데이터베이스제작자 권리, 업무방해)는 모두 무죄.
- 같은 사건의 민사(부정경쟁방지법)는 서울고법이 약 10억 원 손해배상 책임을 인정했다.
- 출처: https://www.scourt.go.kr/sjudge/1652779958317_183238.pdf , https://www.shinkim.com/kor/media/newsletter/1843 , https://bizhankook.com/articles/27377.html

이 프로젝트와 다른 점: 경쟁 사업자가 아니고, 영리 목적이 아니고, 수집량이 훨씬 적다. 그래도 위험이 없다고 할 수는 없다. 걸릴 수 있는 지점은 다음과 같다.

- 저작권법 데이터베이스제작자 권리(제93조): 상당한 부분을 복제하거나, 반복적·체계적으로 복제해서 그와 같은 결과가 생기면 침해가 될 수 있다. 1시간마다 수집하는 건 반복적·체계적 복제에 해당할 수 있으므로 수집 범위를 작게 유지해야 한다.
- 다나와 이용약관: 회사에 권리가 있는 정보를 사전 승낙 없이 영리 목적으로 복제·배포하는 것을 금지한다.
- 부정경쟁방지법: 민사에서 문제가 된 부분. 다나와와 경쟁하는 서비스를 만들거나 수집 데이터로 영리 활동을 하면 위험이 커진다.
- 업무방해, 정보통신망법: 서버에 부담을 주거나 차단을 우회하면 문제가 된다.

그래서 이렇게 수집한다.

1. 소수 상품만. 처음에는 20개 안팎으로 시작한다. 카테고리 전체나 사이트 전체를 긁지 않는다.
2. 1시간에 한 번, 상품 사이에 몇 초씩 간격을 둔다.
3. 상품 페이지에서 가격, 판매처 이름, 수집 시각만 저장한다. 이미지, 상품 설명, 리뷰는 저장하지 않는다.
4. robots.txt가 금지하는 경로(`/api/`, `/list/ajax/`, `/info/ajax/` 등)는 호출하지 않는다.
5. 403, 429, CAPTCHA 같은 차단 응답을 받으면 우회하지 않고 수집을 멈추고 기록한다.
6. 수집한 원본 데이터를 외부에 공개하거나 배포하지 않는다. 공개 데모는 연습 쇼핑몰(mock-shop) 데이터로 만들고, 실데이터는 분석 결과와 기록에만 쓴다.
7. 다나와 화면을 그대로 옮긴 서비스를 만들지 않는다.

이 원칙을 수집기 코드 설정값과 README에도 적어 둔다.
