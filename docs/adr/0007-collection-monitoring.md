# ADR-0007: 수집 감시와 알림

- 날짜: 2026-10-24
- 상태: 채택
- 관련: #10, ADR-0006, TS-0003

## 상황

- 수집은 cron-job.org, GitHub 토큰(2027-01-22 만료), GitHub Actions, Neon, 다나와 화면 구조에 기대고 있다. 어느 하나가 깨지면 수집이 빈다.
- GitHub 예약 실행이 몇 시간 동안 안 돈 것도 Actions 화면을 직접 보기 전까지 몰랐다 (TS-0003).
- 수집이 아예 안 돌면 수집기 코드도 안 돈다. 그래서 "안 돌았다"는 건 수집기 안에서 알아낼 수 없고, 바깥에서 지켜봐야 한다.

## 선택지

### A. Healthchecks.io로 신호가 끊기면 알림 (dead man's switch)

- 수집기가 실행을 마칠 때마다 Healthchecks.io에 신호를 보낸다. 문제가 있으면 `/fail` 주소로 보내고 요약을 본문에 담는다.
- 정해진 시간 안에 신호가 안 오면 Healthchecks.io가 알린다.
- 좋은 점: cron-job.org, GitHub, Neon 중 어디가 멈춰도 "신호가 안 왔다"로 잡힌다. 감시하는 쪽이 감시받는 쪽과 다른 서비스다. 무료 플랜으로 20개까지 감시한다 (https://healthchecks.io/pricing/).
- 걸리는 점: 외부 서비스가 하나 더 늘어난다. 신호 주소를 아는 사람은 가짜 성공 신호를 보낼 수 있어서 Secret으로 다룬다.

### B. GitHub 실패 알림 + cron-job.org 실패 알림

- 실행이 돌았는데 실패하면 GitHub이 메일을 보낸다. 호출이 실패하면(토큰 만료 등) cron-job.org가 알린다.
- 걸리는 점: cron-job.org가 통째로 멈추거나 호출을 건너뛰면 아무도 모른다. 실행은 성공했는데 데이터 품질이 나빠진 경우(파싱 실패가 늘어남)도 못 잡는다. 지금 수집기는 일부 실패면 종료 코드 0으로 끝난다.

### C. cron-job.org가 감시용 워크플로를 따로 실행

- 걸리는 점: 감시와 수집이 같은 cron-job.org와 토큰에 기대서 같이 멈춘다.

## 결정

A. 사용자가 확정했다.

신호 규칙:

- 실행마다 마지막에 한 번 보낸다. 성공이면 체크 주소, 문제가 있으면 `체크 주소/fail`. 본문에는 실행 번호, 상태, 성공 수, 실패한 상품과 원인을 텍스트로 담는다 (Healthchecks.io는 본문 앞 100kB를 로그로 보관한다, https://healthchecks.io/docs/http_api/).
- 수집기에서 예상 못 한 오류가 나도 `/fail`을 보낸다.
- 신호 전송이 실패해도 수집 결과는 그대로 둔다. 신호가 안 가면 Healthchecks.io 쪽에서 "신호 없음"으로 알린다.
- `HEALTHCHECK_URL`이 없으면 신호를 보내지 않는다. 로컬 실행과 테스트에서는 보내지 않게 하려는 것이다.
- 판정에 문제가 있으면 `flowdeck collect`가 종료 코드 1로 끝난다. GitHub Actions 화면에서도 실패로 보이게 하려는 것이다. 전에는 전부 실패일 때만 1이었다.

`/fail`로 볼 기준 (처음 값, 운영하면서 조정):

| 조건 | 이유 |
|---|---|
| 실행 상태가 failed | 하나도 못 모았다 |
| 차단(blocked)이 하나라도 있다 | 수집 원칙상 바로 멈추고 사람이 봐야 한다 (ADR-0004 원칙 5) |
| 요청·파싱 실패가 3개 이상 | 다나와 화면 구조가 바뀌었거나 접근이 막히기 시작한 신호 |
| 판매처 목록 파싱 실패가 3개 이상 | 화면 HTML 쪽 구조가 바뀐 신호. 최저가는 JSON-LD라 계속 모이기 때문에 실행은 성공으로 나온다 |

1~2개 실패는 다나와 쪽 일시 오류일 수 있어서 성공 신호를 보내고 본문에만 남긴다.

Healthchecks.io 체크 설정: 일정은 cron `17 * * * *`, 시간대 Asia/Seoul, 여유 시간(grace) 30분. 수집이 1분 30초 안팎 걸리니 17분 + 30분 안에 신호가 오면 정상이다. 알림은 우선 이메일.

## 감수하는 것

- 외부 서비스가 cron-job.org, Neon, Healthchecks.io로 셋이 됐다. 대신 감시는 나머지와 독립돼 있다.
- 기준 숫자(3개)는 근거 없이 정한 처음 값이다. 실제 실패 패턴을 보고 고친다.
- Healthchecks.io가 멈추면 감시도 멈춘다. 이 경우 가짜 "신호 없음" 알림이 오거나 알림이 안 온다. 수집 자체에는 영향이 없다.
