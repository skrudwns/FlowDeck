# ADR-0006: 수집 주기 실행을 외부 cron의 workflow_dispatch 호출로

- 날짜: 2026-10-24
- 상태: 채택
- 관련: #2, ADR-0003(일부 대체), TS-0003

## 상황

- ADR-0003에서 GitHub Actions 예약 실행(schedule)으로 1시간마다 수집하기로 했다.
- 실제로는 이 저장소에서 예약 실행이 돌지 않았다. 수집 워크플로의 14:17, 15:17 예약, main 커밋으로 재동기화한 뒤에도, echo만 하는 5분 주기 확인 워크플로도 15분 동안 한 번도 돌지 않았다 (TS-0003).
- 같은 워크플로를 수동 실행(workflow_dispatch)하면 정상으로 돈다. 다나와 접근과 Neon 저장까지 확인했다.
- 비용을 들이지 않는다는 조건은 그대로다.

## 선택지

### A. 외부 cron 서비스가 GitHub API로 workflow_dispatch 호출

- 좋은 점: 동작을 확인한 수동 실행과 같은 경로다. 비용이 없다. 실행 환경(GitHub Actions + Neon)은 ADR-0003 그대로 둔다. GitHub 커뮤니티 토론 #185355에, 예약 실행이 76회 중 5회만 돌던 사람이 이 방식으로 바꾼 뒤 목표 시각 35초 안에 실행됐다는 보고가 있다.
- 걸리는 점: GitHub 토큰을 외부 서비스에 맡겨야 한다. 외부 서비스가 멈추면 수집도 멈춘다.

### B. 저장소를 공개로 바꾸고 예약 실행 다시 시도

- 좋은 점: 바로 확인할 수 있고 설정이 거의 없다.
- 걸리는 점: 코드와 커밋 이력이 공개된다. 공개해서 돈다는 보장이 없다. "무료 계정의 비공개 저장소는 예약이 안 돈다"는 주장은 출처가 확인되지 않았다. 2026년에 공개·비공개 상관없이 예약 실행이 불안정하다는 보고가 이어지고 있다.

### C. 노트북 cron

- 잠자기 동안 수집이 빈다. ADR-0003에서 이미 뺀 선택지다.

### D. 클라우드 서버

- 비용이나 카드 등록이 필요하다. ADR-0003에서 뺀 이유가 그대로다.

## 결정

A. 사용자가 골랐다. 수동 실행이 동작한다는 건 확인된 사실이고, 예약 실행은 원인을 알 수 없이 안 도는 상태라서 확인된 경로에 기대는 쪽이 낫다.

- 외부 서비스: cron-job.org (무료). 공식 FAQ에 POST 요청과 본문을 지원한다고 되어 있다 (https://cron-job.org/faq/).
- 호출: `POST https://api.github.com/repos/skrudwns/FlowDeck/actions/workflows/collect.yml/dispatches`, 본문 `{"ref":"main","inputs":{"trigger":"schedule"}}`. 성공하면 200과 실행 ID가 온다 (GitHub REST API 문서, API 버전 `2026-03-10`).
- 토큰: fine-grained personal access token. 이 저장소만, 권한은 Actions 쓰기만. 이 API에 필요한 권한이 "Actions: write"라는 건 GitHub 문서(Permissions required for fine-grained personal access tokens)에서 확인했다.
- 시각: 매시 17분은 그대로 둔다. GitHub 예약 실행이 아니라서 정각 부하와는 상관없지만 바꿀 이유도 없다.
- 워크플로는 `workflow_dispatch`만 받는다. `schedule`은 뺐다. 둘 다 두면 예약 실행이 어느 날 다시 돌기 시작했을 때 한 시간에 두 번 수집하게 되고, 수집 원칙(1시간 1회)을 어긴다.
- 외부 호출은 `trigger=schedule` 입력을 넘겨서, DB 실행 기록에서 사람이 누른 수동 실행(`manual`)과 구분한다.

## 감수하는 것

- 토큰이 외부 서비스에 저장된다. 이 저장소의 Actions 쓰기 권한만 있으니, 새어 나가도 이 저장소의 워크플로를 실행하거나 취소하는 정도다. 코드나 Secrets는 읽을 수 없다.
- 토큰에는 만료일이 있다. 만료되면 호출이 401로 실패하고 수집이 멈춘다. 만료 전에 새로 발급해서 바꿔 넣어야 한다.
- cron-job.org가 멈추거나 정책을 바꾸면 수집도 멈춘다. 실패 알림을 켜 둔다.
