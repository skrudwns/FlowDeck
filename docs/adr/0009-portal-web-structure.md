# ADR-0009: 포털 웹 구조

- 날짜: 2026-10-24
- 상태: 채택
- 관련: #14, ADR-0001, ADR-0008

## 상황

- #14는 조회 화면이다: 작업 목록, 실행 이력과 실패 원인, 가격 표와 차트, 단계 흐름 시각화. 제어 기능은 #16.
- 스택은 ADR-0001에서 Next.js + TypeScript로 정했고, API 타입은 OpenAPI에서 만들기로 했다.
- 이번 결정은 사용자가 따로 고르지 않았고 Claude가 정했다.

## 정한 것

### 프로젝트

- Next.js 16 (App Router), TypeScript, npm. 저장소의 `web/`. 패키지 관리자는 이 Mac에 이미 있는 npm을 쓴다. pnpm을 따로 설치할 이유가 아직 없다.
- 스타일은 create-next-app 기본인 Tailwind CSS. 컴포넌트 라이브러리는 붙이지 않는다. 화면이 몇 개 안 되고, 의존성을 늘리면 관리할 게 늘어난다.

### 데이터 가져오기

- 서버 컴포넌트에서 API를 호출한다. 브라우저가 API를 직접 부르지 않으니 CORS 설정이 필요 없고 API 주소도 브라우저에 드러나지 않는다.
- API 주소는 환경 변수 `FLOWDECK_API_URL`.
- 데이터는 매시 바뀌므로 요청마다 새로 가져온다. 캐시는 느려지면 그때 본다.
- 처음에는 `cache: "no-store"`를 붙이려고 했다. 생성된 프로젝트의 `AGENTS.md`가 "이 버전의 Next.js는 알던 것과 다르니 `node_modules/next/dist/docs/`를 먼저 읽으라"고 해서 읽어 보니, Next.js 16은 `cacheComponents`가 켜져 있으면 fetch가 기본으로 캐시되지 않고, 요청마다 가져오는 데이터와 `params`·`searchParams`는 `<Suspense>` 안에서 읽어야 했다. 그래서 각 화면은 정적인 틀을 먼저 그리고, 데이터 부분은 `<Suspense>`로 감싸 요청 때 채운다. 빌드할 때 API 서버가 없어도 된다.

### API 타입

- FastAPI가 만드는 OpenAPI 문서에서 `openapi-typescript`로 타입을 만들고, `openapi-fetch`로 타입이 붙은 클라이언트를 쓴다. API 응답이 바뀌면 타입 오류로 바로 드러난다.
- OpenAPI 문서는 서버를 띄우지 않고 백엔드 코드에서 바로 뽑는다 (`flowdeck openapi`). 뽑은 파일과 생성된 타입은 저장소에 커밋한다. CI에서 다시 생성해 달라졌으면 실패시킨다.

### 화면

| 경로 | 내용 |
|---|---|
| `/` | 작업 목록(다음 실행 시각, 마지막 결과), 수집 → 가공 → 저장 → 알림 흐름도 |
| `/runs` | 실행 이력 |
| `/runs/[id]` | 실행 하나의 상품별 결과와 실패 원인 |
| `/products` | 상품 표. 이름 검색, 최근 상태로 거르기 |
| `/products/[id]` | 가격 차트, 가격 이력 표, 최근 수집의 판매처 가격 |

- 차트는 Recharts. React 컴포넌트로 쓰고, 선 그래프 하나면 된다.
- 시각은 한국 시간으로 보여준다 (`Intl.DateTimeFormat`, `Asia/Seoul`). API는 UTC로 준다 (ADR-0008).

### 작업 목록을 위한 API

- 지금 작업은 "다나와 가격 수집" 하나다. 작업 정의(이름, 대상, 주기)를 백엔드 코드에 두고 `GET /jobs`로 내보낸다. 다음 실행 시각은 주기(매시 17분)로 계산한다.
- 실제로 실행을 거는 건 cron-job.org다 (ADR-0006). 그래서 주기가 코드와 cron-job.org 두 군데에 있다. 주기를 바꾸면 둘 다 고쳐야 한다. 포털에서 주기를 바꾸는 기능(#16)에서 하나로 합친다. (ADR-0011에서 주기는 DB로, cron-job.org는 매시 확인 호출만 하게 바꿈)
