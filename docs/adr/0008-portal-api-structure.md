# ADR-0008: 포털 API 구조

- 날짜: 2026-10-24
- 상태: 채택
- 관련: #11, ADR-0001, ADR-0005

## 상황

- 포털 웹과 나중의 앱 연동은 모두 API를 통한다 (ADR-0001, API 우선 설계).
- #11은 읽기 전용 API다. 쓰기·제어(수동 실행, 주기 변경)는 #16에서 한다.
- 수집기는 SQLAlchemy 동기 세션으로 DB를 쓰고 있다 (ADR-0005).

## 정한 것

이번 결정은 사용자가 따로 고르지 않았고, Claude가 정했다. 바꿀 이유가 생기면 이 문서를 고친다.

### 동기 엔드포인트 + 기존 동기 세션

- FastAPI는 `def` 엔드포인트를 스레드 풀에서 돌린다. 수집기와 같은 모델, 같은 세션 팩토리를 그대로 쓴다.
- async(asyncpg, AsyncSession)로 가면 DB 접근 코드를 두 벌 관리하게 된다. 지금 트래픽은 포털 사용자 몇 명 수준이라 비동기의 이점을 볼 일이 없다.
- 감수: 동시 요청이 아주 많아지면 스레드 풀 크기가 한계가 된다. 그때 다시 본다.

### 엔드포인트

| 경로 | 내용 |
|---|---|
| `GET /health` | API와 DB 연결 확인 |
| `GET /products` | 수집 대상 목록과 각 상품의 최근 수집 결과(최저가, 판매처 수, 시각) |
| `GET /products/{id}` | 상품 하나 |
| `GET /products/{id}/prices` | 상품의 가격 이력. 기간(`since`, `until`)과 개수(`limit`)로 자른다 |
| `GET /snapshots/{id}/sellers` | 수집 한 번의 상위 판매처 가격 |
| `GET /runs` | 수집 실행 이력. 최신순, `limit`·`offset` |
| `GET /runs/{id}` | 실행 하나와 상품별 결과(실패 원인 포함) |

- 상품은 DB의 `id`로 가리킨다. 다나와 pcode는 응답에 `source_product_id`로 넣는다. 나중에 다른 수집 대상(연습 쇼핑몰)이 붙어도 경로가 같다.
- 목록은 `limit`(기본 50, 최대 500)과 `offset`으로 자른다. 커서 방식은 데이터가 많아지면 다시 본다.
- 가격 이력은 차트에 한 번에 그릴 수 있게 `limit` 기본 500, 최대 2,000으로 따로 잡았다. 매시 수집이면 한 달에 약 720개다. 시간 오름차순으로 주고, 제한을 넘으면 가장 최근 것을 남긴다.
- 실패한 수집도 가격 이력에 상태와 함께 넣는다. 그래야 화면에서 수집이 빈 구간이 보인다.
- 시각은 DB에 UTC로 저장돼 있고, 응답도 오프셋이 붙은 ISO 8601로 준다. 한국 시간으로 보여주는 건 화면에서 한다.
- 응답 형식은 pydantic 스키마로 따로 정의한다. DB 모델을 그대로 내보내지 않는다. 테이블을 바꿔도 API 응답이 바로 바뀌지 않게 하려는 것이다.

### 범위 밖

- 인증: 지금은 로컬에서만 띄운다. 배포할 때 정한다.
- CORS: 웹(#14)을 붙일 때 허용 주소를 정한다.
