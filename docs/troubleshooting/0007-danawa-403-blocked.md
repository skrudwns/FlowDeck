# TS-0007: 11-11 21:17 KST부터 다나와가 수집기에 403을 돌려줌

- 날짜: 2026-11-11
- 관련: #53, ADR-0004(수집 원칙 5), ADR-0007, ADR-0011
- 상태: 임시 해결 (다나와 정기 수집 중지, 차단 원인 모름)

> 요약: 11-11 21:17 KST부터 다나와가 수집기 요청에 403을 돌려줬다. 수집기는 원칙 5대로 첫 상품에서 멈췄다. 차단 이유는 모르고, 우회 확인은 하지 않았다. 사용자 결정으로 다나와 정기 수집을 껐다.

## 증상

사용자가 GitHub Actions 실패 메일("가격 수집: All jobs have failed", collect, Failed in 1 minute and 10 seconds)을 보여 주며 원인을 물었다.

## 근거

Actions 가격 수집 실패 실행 (2026-11-11 22:29 KST에 API로 조회, 최근 100개 중):

```
444 43027735527 failure 2026-11-11T13:17:08Z 7017c76
443 43019007243 failure 2026-11-11T12:17:08Z 7017c76
417 42797835906 failure 2026-11-10T10:17:09Z 7017c76
```

세 번 모두 "다나와 수집" 단계만 실패했다. 443, 444는 다나와 단계가 8~10초 만에 끝났다. 주석은 `Process completed with exit code 1.`뿐이다.

Neon 수집 실행 기록 (KST):

```
(815, 'danawa', 2026-11-10 19:17:32, 'failed', 0, 20, None)
(863, 'danawa', 2026-11-11 19:17:30, 'success', 20, 20, None)
(865, 'danawa', 2026-11-11 20:17:31, 'success', 20, 20, None)
(867, 'danawa', 2026-11-11 21:17:30, 'failed', 0, 20, '상품 18297722에서 차단 응답 403. 남은 상품은 수집하지 않음')
(869, 'danawa', 2026-11-11 22:17:30, 'failed', 0, 20, '상품 18297722에서 차단 응답 403. 남은 상품은 수집하지 않음')

```

## 원인 찾기

| 가설 | 확인 방법 | 결과 |
|---|---|---|
| 11-10 19:17 실패와 같은 원인 | 스냅샷 오류 | 아님. 11-10은 연결 시간 초과(20개 모두), 다음 실행부터 정상 |
| 다나와가 수집기 요청을 차단 | 실행 기록, 스냅샷 | 21:17, 22:17 두 번 연속 첫 상품에서 403. 수집기는 원칙 5대로 남은 상품을 요청하지 않고 멈췄다 |

- 403이 상품 페이지에서 났는지 robots.txt에서 났는지는 이 기록으로 구분되지 않는다. robots.txt도 같은 경로(`PoliteClient._get`)로 받고, 거기서 403이 나도 같은 문구로 남는다.
- 차단 이유(Actions 러너 IP 대역, User-Agent, 요청 빈도 등)는 모른다. 원칙 5에 따라 다른 IP나 다른 User-Agent로 다시 요청해 보는 확인은 하지 않았다.
- 끄기 전까지는 정기 실행이 매시 돌았다. 실행마다 robots.txt와 첫 상품 페이지, 많아야 요청 두 번을 보낸 뒤 멈췄다.

## 조치

- 사용자가 "다나와 수집 끄기"를 골랐다. 2026-11-11 22:40 KST에 포털 API(`PATCH /jobs/danawa-prices {"enabled": false}`, 로컬 API를 Neon에 붙여 호출)로 다나와 정기 수집을 껐다. 변경 이력:

```
id 3, 2026-11-11T13:40:58Z, actor portal, schedule_changed, danawa-prices, "매시 17분 → 매시 17분, 꺼짐"
```

- 연습 쇼핑몰 수집은 그대로 돈다. plan 단계는 돌지 않는 작업에도 Healthchecks 신호를 보낸다(ADR-0011).
- 끈 뒤 첫 정기 실행(23:17 KST, Actions 445)은 success였고, Neon에는 연습 쇼핑몰 실행(871, 8/8)만 생겼다. 다나와에는 요청하지 않았다.

## 남은 것

- 차단 이유. 다시 켤지, 언제 어떻게 켤지는 정하지 않았다.
- 11-11 21:17부터 다나와 데이터가 없다. 10-24부터 쌓은 데이터로 하려던 3~4주 재평가(AN-0005 다음 할 일)는 11-11까지의 데이터로 해야 한다.
