# TS-0001: push된 커밋을 amend해서 로컬과 원격 브랜치가 갈라짐

- 날짜: 2026-10-24
- 관련: #2, 커밋 `5317ee7`(원격), `e83bc56`(로컬, amend 결과)
- 상태: 미해결

> 요약: 원격에 이미 push된 커밋을 "push 전"이라고 생각하고 amend했다. 같은 변경이 해시만 다른 두 커밋으로 갈라졌다.

## 증상

2026-10-24, 브랜치 상태를 확인하다가 원격에 `feat/2-real-price-collector`가 이미 있고, 로컬과 서로 다른 커밋을 갖고 있는 걸 발견했다.

```
원격에 없는 로컬 커밋: 8
로컬에 없는 원격 커밋: 1
원격 최신: 5317ee7 docs(docs): CLUADE 규칙 문서 업데이트
```

## 원인 찾기

| 가설 | 확인 방법 | 결과 |
|---|---|---|
| 원격의 `5317ee7`이 로컬에서 amend한 커밋의 원본이다 | `git reflog` | 맞음. 02:50:48 `5317ee7` 커밋, 02:52:35 amend로 `e83bc56` 생성 |

```
e83bc56 HEAD@{2026-10-24 02:52:35 +0900}: commit (amend): docs: 이슈 단위로 PR 생성과 병합까지 하도록 작업 규칙 변경
5317ee7 HEAD@{2026-10-24 02:50:48 +0900}: commit: docs(docs): CLUADE 규칙 문서 업데이트
```

## 원인

- 사용자가 CLAUDE.md 변경을 직접 커밋하면서 브랜치를 원격에 올렸다(`5317ee7`).
- Claude는 원격을 확인하지 않고 "아직 push 전"이라고 판단해서 커밋 제목 오타를 amend로 고쳤다.
- amend는 커밋을 새로 만들기 때문에 원격의 `5317ee7`과 로컬의 `e83bc56`이 서로 다른 커밋이 됐다. 그 위에 로컬 커밋이 계속 쌓였다.

## 해결

아직 정하지 않았다. 선택지:

- (a) 원격 브랜치를 로컬로 덮어쓰기(`git push --force-with-lease`). 아직 PR이 없고 이 브랜치를 쓰는 사람이 한 명이라 영향은 이 브랜치에 한정된다. 원격의 `5317ee7`은 사라진다.
- (b) 원격을 로컬에 merge. 기록은 다 남지만 같은 변경이 커밋 두 개(`5317ee7`, `e83bc56`)로 이력에 남는다.

## 배운 것

- 커밋을 amend하거나 rebase하기 전에 `git fetch` 후 `git status -sb` 또는 `git rev-list origin/<브랜치>..HEAD`로 원격에 이미 있는지 확인한다. "push 전"이라는 판단을 기억이나 짐작으로 하지 않는다.
- 데스크톱 앱 등에서 커밋하면 push까지 같이 될 수 있다.
