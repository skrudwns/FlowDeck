## 판단과 근거

### 분석 데이터

- 처음에 "연습 쇼핑몰 과거 데이터로 지금 분석을 시작하자"고 제안했다. 사용자가 그게 우리가 만든 목데이터라는 뜻인지 물었고, 맞다고 답했다. 사용자의 목적은 "실데이터로 분석또한 실전성있게 깊이있는 분석을 하기 위함"이었다. 목데이터에서 찾은 패턴은 우리가 넣은 패턴이라 시장에 대해 알려주는 게 없다. 그래서 연습 쇼핑몰 데이터는 코드가 넣은 패턴을 찾는지 확인하는 데만 쓴다.
- 다나와는 과거 이력을 원칙상 못 받으니 쌓이는 만큼만 쓴다. 10-24부터 매시 쌓이고 있다.
- 사용자가 "다른 신뢰할만한 대량의 분량의 실데이터 검증을 병행해서 다른 분석과 비교를 통해 우리의 분석 능력과 알고리즘의 타당성 검증에 활용"하자고 했다. 우리 데이터만으로는 알고리즘이 맞는지 스스로 증명할 수 없다는 점에 맞춰 검증을 세 층으로 나눴다.

| 층 | 데이터 | 비교 대상 |
|---|---|---|
| 단위 정답 | 연습 쇼핑몰 | 가격 규칙의 정답 |
| 라벨 있는 벤치마크 | TCPD | 같은 데이터로 평가된 알고리즘 14개의 논문 점수 |
| 연구 결과 재현 | Cavallo(2017), 가능하면 Dominick's | 논문 수치 (온·오프라인 같은 가격 72% 등) |
| 공식 통계 대조 | 참가격 | 통계청 소비자물가 품목 지수 |
| 적용 대상 | 다나와 | 위에서 확인한 정확도 |

- 후보 중 Keepa는 유료(월 €49부터라는 자료)라 뺐다. Dominick's는 학술 전용이고 Kilts Center 구독 목록에 있어 쓸 수 있는지 불확실하다. TCPD 데이터와 NAB의 라이선스, Cavallo 복제 자료의 공개 위치는 아직 확인하지 못했다. 이건 #29에서 확인한다.

### 분석 환경 (#13)

- ADR-0001은 탐색용으로 Jupyter 노트북을 적었는데, `# %%`로 셀을 나눈 파이썬 스크립트로 했다. 터미널에서 그대로 돌고, 노트북처럼 셀 단위로 열 수도 있다. .ipynb는 출력이 파일에 섞여 변경 내역을 읽기 어렵다. Claude가 정했다.
- 받은 원본(`analysis/data/`)은 `.gitignore`로 막았다. 저장소에는 집계와 그래프만 남긴다 (ADR-0004 수집 원칙 6).
- 분석 프로젝트가 백엔드 패키지를 경로 의존성으로 쓴다. DB 주소 변환(`sqlalchemy_url`)을 두 번 쓰지 않으려는 것이다.

### 잘못 저장된 배송비 (#33)

- 1만 원 이상 다나와 배송비 11가지 값(5,050행)이 모두 "시각 숫자 + 정상 배송비"로 설명됐다. 예: 33,000 = 3시 + 3,000원, 122,900 = 12시 + 2,900원. 시각은 안내 문구에 나오는 1~5시, 12시뿐이었다.
- 선택지: 규칙으로 복원, NULL로 비우기, 그대로 두고 분석 때만 보정. 운영 DB를 바꾸는 일이라 사용자에게 물었고 사용자가 규칙 복원을 골랐다.
- 마이그레이션은 규칙에 맞지 않는 값이 하나라도 있으면 아무것도 바꾸지 않고 멈춘다. 병합 전에 같은 규칙을 Neon에 읽기 전용으로 돌려 설명 안 되는 값이 0개인 것을 확인했다. 복원한 대응은 audit_log에 남긴다.
- #29보다 #33을 먼저 했다. 고치지 않으면 매시 잘못된 배송비가 계속 쌓이기 때문이다. Claude가 제안했고 사용자가 "#33 먼저"로 정했다.

## 문제

- 이슈를 등록하려는데 내장 브라우저의 GitHub 로그인이 풀려 로그인 화면이 떴다. 비밀번호는 Claude가 입력하지 않으므로 GitHub이 필요 없는 #12 측정을 먼저 했고, 사용자가 다시 로그인한 뒤 이슈를 등록했다.

- AN-0001에서 배송비를 넣은 1위를 계산했더니 61.3%에서 1위가 바뀌고 차이 중앙값이 74,000원이었다. 값이 너무 커서 배송비 분포를 보니 33,000원 같은 값이 5,050행이었다. pcode 77319515 페이지를 수집기 User-Agent로 한 번 다시 받아 확인했다. 배송비 칸 안의 빠른배송 안내 문구("낮 3시 이전 주문 시…")의 숫자까지 이어 붙이고 있었다. 수집 시작부터 있던 버그다. 같은 페이지에서 목록에 현금가가 섞여 있고 가격순이 아닌 것도 봤다. 둘 다 #33으로 따로 고친다.
- devlog 2026-10-24에 키오시아 최저가를 "46% 올랐다"고 적었다. AN-0001에서 판매처 목록을 보니 첫 수집 때 있던 G마켓 특가(403,190원)가 끝난 것이었다. 그 주 시세는 59만 원대였다.

- `price_label` 마이그레이션을 확인하면서, 새 마이그레이션을 적용하기 전에 `alembic downgrade -1`을 해서 그 전 마이그레이션(제어 테이블)을 되돌렸다가 다시 만들었다. 로컬 개발 DB라 운영에는 영향이 없었고, 로컬의 실행 요청과 변경 이력 행이 지워졌다. push 전이어서 "확인했다"고 적은 커밋 메시지를 실제로 확인한 내용으로 고쳤다.
- 로컬 Postgres가 꺼져 있어서 처음에는 DB 테스트 84개가 건너뛰어진 채 "47 passed"로 끝났다. `docker compose up`이 응답 없이 멈춰서 `docker start flowdeck-db-1`로 띄운 뒤 131개를 돌렸다.

## 배운 것

- 최저가 하나만 보고 해석하면 짧은 특가가 시세처럼 보인다. 판매처 목록을 같이 봐야 원인이 나온다 (키오시아).
- 집계 숫자가 이상하게 크면 원문을 다시 본다. 배송비 버그는 1주 동안 감시에 걸리지 않았다. 감시는 파싱 실패만 세고 값의 범위는 보지 않는다.
- 마이그레이션을 되돌려 확인할 때는 먼저 `alembic current`로 지금 위치를 본다. 새 마이그레이션을 적용하기 전에 `downgrade -1`을 하면 엉뚱한 단계가 되돌아간다.
- 테스트 결과에 skipped가 많으면 통과로 보지 않는다. DB가 꺼져 있으면 DB 테스트가 조용히 건너뛰어진다 (CI는 `REQUIRE_TEST_DB`로 실패시킨다).
- 행 크기를 추정할 때 열 데이터만 보면 작게 나온다. 판매처 가격 한 행의 열 데이터는 평균 63바이트였는데, 인덱스와 행 헤더를 포함한 실제 크기는 106바이트였다.
