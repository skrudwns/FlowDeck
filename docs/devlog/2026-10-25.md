## 판단과 근거

### 가격을 시각만으로 정함

- 쇼핑몰은 수집 작업 안에서 매시간 새로 뜬다. 서버가 가격 상태를 들고 있으면 매번 처음 상태로 돌아간다.
- 그래서 가격은 상품, 판매처, 한국 시간 기준 날짜와 시만으로 계산한다. 난수 대신 `sha256(상품|판매처|날짜|규칙)` 값을 쓴다. 같은 시각이면 어디서 띄워도 같은 가격이 나오고, 지난 시각의 정답도 다시 계산할 수 있다.
- 규칙 확률을 정한 뒤 2026-10-26부터 4주를 계산해 세어 봤다. 상품·판매처 26쌍 × 28일 = 728건 중 급락이 있는 날 96건(13.2%, 정한 값 1/7 = 14.3%), 품절은 품절될 수 있는 504건 중 65건(12.9%, 정한 값 10%), 주말 할인은 바사스토어가 파는 7개 상품 × 주말 8일 = 56건. 데모 기간에 세 패턴이 모두 나온다.

### 쇼핑몰 형태와 저장

- 판매처 여러 곳이 한 상품을 파는 가격 비교 사이트 형태로 만들었다. 다나와와 같은 테이블, 같은 포털 화면을 쓸 수 있다.
- 페이지 구조는 다나와와 다르게 만들었다(JSON-LD 없이 표). 수집 대상마다 파서를 따로 두는 구조가 실제로 필요해진다.
- 품절 판매처도 `in_stock=false`로 저장한다. 목록에서 빠진 것만 보고는 품절인지 파싱이 잘못된 건지 나중에 구분할 수 없다. 최저가와 판매처 수는 재고 있는 판매처만으로 계산한다.
- 상품 전체 품절은 뺐다. 상품마다 품절되지 않는 판매처를 하나 둔다. 전체 품절을 넣으면 스냅샷 상태, 감시 기준, 화면을 같이 고쳐야 한다.
- 빈 상품 목록은 파싱 실패로 본다. 그대로 받아들이면 목록에 없는 상품을 비활성화하는 규칙 때문에 모든 상품이 비활성화된다.

### 실행

- 다나와와 연습 쇼핑몰을 같은 워크플로의 다른 작업으로 나란히 돌린다. cron-job.org 호출을 하나 더 만들 필요가 없고, 한쪽이 실패해도 다른 쪽은 돈다.
- 두 작업이 동시에 `alembic upgrade head`를 하면 같은 마이그레이션을 두 번 적용하려 할 수 있어서 `migrate` 작업을 앞에 두고 두 수집 작업이 기다리게 했다.
- Healthchecks 체크는 따로 둔다. 같은 체크를 쓰면 `/fail`이 왔을 때 어느 쪽 문제인지 알 수 없다. 판정 요약 첫 줄에도 수집 대상을 넣었다.
- 백엔드 파서 테스트의 HTML은 쇼핑몰 코드로 만든다(`mock-shop fixtures`). 쇼핑몰 HTML만 바꾸고 테스트 HTML을 다시 만들지 않는 경우를 CI에서 다시 만들어 비교해 잡는다. 웹 API 타입(ADR-0009)과 같은 방식이다.

### 병합 전에 운영 DB로 돌려 보지 않음

- 새 `collection_runs.source` 컬럼은 기본값이 없다. 마이그레이션이 Neon에 들어간 뒤 main의 옛 코드가 돌면 실행 기록을 넣다가 실패한다.
- 브랜치에서 수집 워크플로를 수동 실행하면 그 순간 Neon 스키마가 바뀌고, 병합 전까지 매시 수집이 실패한다. 그래서 병합한 뒤 main에서 수동 실행해 확인하기로 했다.

## 문제

- Alembic 자동 생성 마이그레이션이 `source`를 기본값 없는 NOT NULL 컬럼으로 추가했다. 로컬 DB에 실행 기록이 2건 있어서 그대로 적용하면 실패한다. 적용 전에 파일을 읽다가 봤다. 기존 행을 `danawa`로 채우는 기본값으로 추가하고 바로 기본값을 없애게 고쳤다. 로컬에서 upgrade, downgrade, upgrade를 돌려 기존 2건이 `danawa`로 채워지는 것을 확인했다.
- 포털 화면에서 연습 쇼핑몰 마지막 실행이 02:50으로 나와서, 수집 로그의 02:50을 UTC로 보고 한국 시간 변환이 안 된다고 생각했다. `date`로 보니 이 Mac의 시간대가 KST였고 로그도 한국 시간이었다. API는 `17:50:05Z`를 주고 있었고 화면이 맞았다.

## 수정

- 처음에는 `mock-shop fixtures`가 TestClient로 페이지를 요청해 파일을 만들게 짰다. TestClient는 개발 의존성(httpx2)이 있어야 돌아서, 페이지 HTML을 만드는 부분을 라우트에서 함수로 떼어 내고 그 함수를 직접 부르게 바꿨다.

## 배운 것

- Alembic autogenerate는 기존 행이 있는지 모른다. 기존 테이블에 NOT NULL 컬럼을 넣을 때는 채울 값을 마이그레이션에 직접 넣는다.
- 이 저장소는 수집 실행마다 `alembic upgrade head`를 하므로 main 병합이 곧 운영 반영이다. 옛 코드와 맞지 않는 스키마 변경은 브랜치에서 운영 DB로 돌려 보지 않는다.
- 로그 시각은 시간대를 확인하고 읽는다. 파이썬 logging의 `asctime`은 로컬 시간이다.
